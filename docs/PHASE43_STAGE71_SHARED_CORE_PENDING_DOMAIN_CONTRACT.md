# Phase 4.3 Stage 7.1 — Shared Core Pending-Domain Intake

Processing scope is not research Domain classification. A clean private Source can start on Workbench schema 9, 10, or 11 without a Source Domain assignment. Its processing basis uses `run-processing-context-v2`, `SHARED_CORE_PENDING`, `PENDING`, no primary Domain, and no packs. The `shared-core-processing-v1` identity binds the two provider operation prompts, canonical Node and Relation enums, Claim–Node roles, and source/semantic evidence rules. The current CloudProfile still binds provider, model, runtime, configuration, limits, and retry policy.

`run-domain-context-v1` remains the historical contract for explicitly assigned Domain runs. It still requires assignment revision greater than zero, a nonempty pack composition, a primary Domain, and `OFFLINE_REPLAY_ONLY`. A nonfake provider is blocked with `DOMAIN_ACTIVATION_REQUIRED`. The new v2 contract uses `LIVE_SHARED_CORE_BOUNDED` and the existing durable CloudJobs and SourceOperations provider checks; it does not activate an Industry Domain Pack.

Both context versions use the existing schema 11 run and packet binding tables. New pending runs set `domain_context_required=1`; old runs marked `0` remain `LEGACY_NO_DOMAIN_CONTEXT`. The packet companion continues to bind the packet hash to the frozen context hash. A later operator Domain assignment changes Source metadata but does not relabel or invalidate an old pending run or its packet. Reprocessing on the new assigned basis requires an explicit `reprocess_reason` and creates a new v1 run. No automatic Domain or Company attribution is made.

Community preview defaults to Shared Core Pending. Community import requires a canonical Company and accepts an optional registered primary Domain. Without one, it creates no `domain_assignments` row. It keeps the Stage 7 low-trust clue provenance and event order. Reimport of the same bundle, Company, and scope is idempotent; changing scope cannot silently reuse an existing run. Generic PDF intake follows the same pending processing path without a Company target.

Review and Company Materials display the frozen run scope. Stage 1 projection uses the frozen context for Domain filters, so pending packets count toward WIP and never appear under an invented Domain. Provider inputs remain Source-local; Company intent, Community summaries, and suggested Domains are not evidence or prompt authority. Human Review and Attribution authority remains unchanged. No Production write or Current View write is part of this contract.
